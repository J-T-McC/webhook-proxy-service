| Database | **MySQL only — SQLite is not usable.** Local: MySQL `8.4` via Sail (`compose.yaml`) · CI: MySQL `8.0` service container · Migrations: Laravel migrations | **The migration set cannot run against SQLite, so SQLite is not a working local default despite `DB_CONNECTION=sqlite` in `.env.example` and `config/database.php`'s `'default' => env('DB_CONNECTION', 'sqlite')`.** The specific reason: `database/migrations/2026_08_04_000002_create_webhook_events_table.php` issues ``DB::statement('ALTER TABLE `webhook_events` ADD `body` LONGBLOB NOT NULL AFTER `content_type`')``. Both the `LONGBLOB` type and the `AFTER` clause are MySQL-only, and SQLite's parser rejects the statement outright, so `php artisan migrate` (and therefore `composer setup`, which runs it) fails partway through. **That raw statement is deliberate and is not the half to change** — Blueprint's `binary()` maps to MySQL `BLOB` (64 KiB), too small for the encrypted body envelope at the ADR-006 cap, per ADR-010 Amendment B. Three later migrations use raw MySQL DDL for the same reason (`2026_08_05_000001`, `2026_08_05_000002`, `2026_08_12_000004`), so the constraint belongs to the migration set as a whole rather than to one file. **A local `.env` must set `DB_CONNECTION=mysql` together with the `DB_HOST`/`DB_PORT`/`DB_DATABASE`/`DB_USERNAME`/`DB_PASSWORD` lines that `.env.example` ships commented out**; under Sail, `DB_HOST` is the `mysql` service. Note the local and CI engines differ by minor version (8.4 in `compose.yaml`, 8.0 in the CI service). **Production engine not yet ratified** — Owner decision, though the schema above already narrows it to MySQL. Cache/session default to `database` driver in `.env.example`. **The queue now defaults to `redis`** — Laravel Horizon supervises Redis queues only, and on `database` it runs while showing nothing, because it watches a queue the application never writes to. (SQLite finding verified 2026-08-27.) |
