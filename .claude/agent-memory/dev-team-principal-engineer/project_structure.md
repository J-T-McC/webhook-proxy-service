**ADRs live in `docs/architecture/`**, named `adr-NNN-<slug>.md` (not `docs/adr/` — task prompts sometimes say that; the real convention is `docs/architecture/`). Sequential; ADR-001..018 exist as of 2026-08-25. Template: dev-team plugin `templates/adr.md` (sections: Question, Decision, Alternatives, Reasoning, Impact). Status starts **Proposed**, becomes **Accepted** on Project Owner approval.

**Ingest→delivery dispatch seam (ADR-001/005/007) — two run-sync-or-queue `lorisleiva/laravel-actions`:** `App\Actions\ProcessIngestedWebhook` (pipeline-level: runs the whole native `Illuminate\Pipeline\Pipeline` over one in-memory `PipelineContext`) and `App\Actions\DeliverToDestination` (per-destination). `::run` = sync inline; `::dispatch` = queued. Steps (e.g. `DeliverStep`) are `AsObject`, never queued individually. Gotcha: **`webhook_events` is raw-only immutable by construction (ADR-010)** — it cannot hold dispatch/processing/claim state, so any per-event ordering/claim state (e.g. #4 FIFO) needs a **sidecar table**, and queued jobs should dispatch **by reference** (`ingest_id`, rebuild `PipelineContext` from the `webhook_events` row on the worker) rather than serialize the `Proxy` model or the raw body (up to the ADR-006 body cap). `delivery_attempts` is payload-free (ADR-003). Data-model changes (new columns/tables) are a **CLAUDE.md Owner-approval gate** — never PE-self-certified.

**Payload-storage table topology (gotchas that bite any lifecycle/GC work):**
- `webhook_events.body` is **`LONGBLOB` added via a raw `DB::statement('ALTER TABLE …')`**, not Blueprint — `$table->binary()` maps to MySQL `BLOB` (64 KiB), too small for the `encrypted` cast envelope (~35% overhead) at the ADR-006 body cap. Any new payload-content column must repeat this. `byte_size` is always the **plaintext** length, computed before the cast. Migrations on this table are therefore **MySQL-only** by precedent, even though `.env.example`/`config/database.php` default to SQLite (CI is MySQL 8.0).
- **A MySQL `json` column can never carry Laravel's `encrypted*` cast.** `webhook_events.headers` is `json`; MySQL validates JSON on write and the cast emits a base64 envelope ⇒ error 3140 on every write. Encrypting any `json` column means a type change to `MEDIUMTEXT` (not `TEXT` — 64 KiB minus ~35% envelope is a silent-truncation cliff) plus a drop-and-re-add, since existing plaintext rows can't be decrypted by the new cast. `content_type` is denormalised into its own column by `WebhookEventCapture::contentTypeFrom()` from the **in-memory** header array before any cast — so it is unaffected by header casts and survives header erasure.
- Every read of `webhook_events.headers` is an Eloquent attribute access; ADR-008 forwarding filters in memory (`DeliveryUnit::forwardHeaders()` over a constant `STRIPPED_HEADERS`). **No `whereJson*`/`JSON_EXTRACT`/header index exists anywhere** in `app/`, `database/`, `tests/` — verified 2026-08-05. `DeliverStep` passes the *same* header array to every destination; only `method` varies per destination (`destinations.http_method`).
- `fifo_dispatches.webhook_event_id` is **`constrained()` = RESTRICT** (as are all `team_id`/`proxy_id` FKs on `webhook_events`/`delivery_attempts`/`fifo_dispatches`). Deleting a `webhook_events` row therefore **fails** unless its `fifo_dispatches` row is deleted first — useful as a fail-loud safety net, fatal if unnoticed.
- `delivery_attempts` reaches an event only through **`ingest_id` (plain uuid column, no FK, plain index)** — so attempt rows are constraint-decoupled from event rows and survive an event delete automatically (ADR-003's "attempt records on their own lifecycle" is structural).
- `webhook_events` indexes are `(team_id, created_at)` and `(proxy_id, created_at)` — a bare `created_at` range scan has no index; scan per team/proxy.
- The `AdvanceProxyFifoQueue` claim locks only `status IN (pending, claimed)` rows under `(proxy_id, status, webhook_event_id)`; work touching only `settled` rows occupies a disjoint index range.

**Mode / enhanced-configuration seams (verify before designing any mode-conditional behaviour):**
- `proxies.mode` is read **behaviourally in exactly one place**: `PipelineFactory::stepsFor()` (two `ProxyMode::Enhanced` branches over the same `$proxy`). Every other `mode` hit in `app/` is CRUD/validation/cast/serialization — grep `ProxyMode|->mode` to re-verify cheaply. Enhanced-only *steps* are gated structurally by composition; enhanced-only *configuration* (retry policy, later #8 maps) is gated at **resolution time** inside its single resolver service, because it is consulted outside the pipeline (settle time, delayed retries) and can never be a step.
- **Single-resolver services are the choke points**: `RetryPolicy` (nominally the only reader of the two `proxies.retry_*` columns and of `config('retry.*')`), `StoredPayloadLookup` (only interpreter of `dispatched_payloads.body IS NULL` and of `payload_cleaned_at`), `RetentionPolicy`. Guard new `config()` reads with the `positiveConfigInt()` fail-loud idiom. Two standing breaches to check before leaning on the invariant: `SweepDueRetries` reads `retry.sweep_grace_seconds` directly (blank env ⇒ `(int)'' = 0` ⇒ cutoff `now()` ⇒ sweeps every retrying delivery every minute), and `ProxyResource` reads the two retry columns directly.
- **`ProxyResource` is one class serving three surfaces** — `index()`, `show()` **and** `edit()`. Anything added to it lands on read *and* write surfaces at once; splitting a write-only field means a second resource class, not a flag. `create()` renders no proxy resource at all (Create.vue hard-codes the blank initial state).
- **Frontend display helpers key off `null`, not off mode**: `proxyRetryAttemptLimitDisplay(null)` renders `5 (default)`, a configured `5` renders bare `5`. So a resource that emits the *effective* value silently changes the Show card's rendering for every unconfigured proxy — emit `null` to mean "the system default governs".
- **`ProxyForm.vue`'s two retry fields have two distinct provenances, and conflating them destroys user data.** A **mount seed** (`props.initial.retry*`, served by `ProxyFormResource`; never mutated, so always available to restore from) vs **in-session typed** input. `watch(isEnhanced, …)` fires only on an in-session mode **change**, never on mount. It shipped with only a *down* arm (clear on Enhanced→Simple); with no *up* arm, an abandoned in-session downgrade (design-07 Flow C step 3 — an explicitly designed path) re-rendered the fieldset blank and the next Enhanced save wrote NULL over the persisted policy. That was review-07's Major, and plan-07 § Technical ruling 4 originally *forbade* fixing it by calling the lost values "in-session typed" — check a ruling's framing against a real reproduction before treating it as binding. The ruling now requires a symmetric up arm re-seeding from `props.initial` with the mount-time `?? ''` normalisation, **unconditionally** (idempotent, and makes the Create and NULL-column cases fall out with no branch — never write a default literal into a field, or an unconfigured proxy silently becomes a configured one). The submit `form.transform()` keys off the **submitted mode**, never field state — that, not the clearing, is what keeps `prohibited_if:mode,simple` satisfiable.
- **Nothing snapshots mode or policy.** Queued jobs are by-reference (`ingestId`/`dispatchUuid`, `deliveryId`/`attemptNumber`); the proxy is re-loaded per run/settle, so "current config governs" is structural. `DeliverToDestination` compares `attemptNumber >= limit` (not `==`), so a shrinking limit terminalizes instead of looping.
- **Gotcha:** `Delivery::proxy()` / `DeliveryAttempt` relations are plain `belongsTo` while `Proxy` uses `SoftDeletes` → `$delivery->proxy` is **null** for a soft-deleted proxy and blows up at runtime in `settleDelivery()`/`DeliveryResource`; PHPStan can't see it (`@property-read Proxy $proxy`). `ProcessIngestedWebhook` is the correct precedent (`Proxy::withTrashed()->findOrFail`).

**A pipeline step that returns `$ctx` without `$next` strands the dispatch — and on FIFO that is fatal.** `ProcessIngestedWebhook` creates the `deliveries` rows (`pending`) *before* running the pipeline, so any step that short-circuits leaves them non-terminal. `AdvanceProxyFifoQueue::settleOrHold()` then parks the `fifo_dispatches` row at `awaiting_retry` **with no lease and no retry schedule** — `SweepStalledFifoDispatches` pass (b) skips the proxy (a held row exists) and pass (c) won't release it (deliveries non-terminal) — so the proxy's line stalls **permanently** and hold **H2 (no age escape)** immortalizes every one of its payloads. Async strands more quietly (badge reads pending forever; H5 still releases). Any new short-circuiting step must first CAS the dispatch's `pending`/`retrying` deliveries → `failed` (+ `DeliveryExhausted` once per affected row, **no** `delivery_attempts` row — the `RetryDelivery::terminalizeCleaned()` precedent); `settleOrHold`/`fifo_dispatches` then need no touching. **`CaptureDispatchedStep`'s cleaned-parent short-circuit (`:70-74`) has this bug today** — narrow (GC must erase *during* a dispatch), unfixed as of 2026-08-26.

**Retry ≠ replay, mechanically.** `RetryDelivery` re-sends `StoredPayloadLookup::dispatchedBytesFor()` — the *recorded dispatched bytes* — so retries never re-run the pipeline and never re-apply a transform. Replay mints a new `dispatch_uuid` and re-runs `ProcessIngestedWebhook` over the whole pipeline from the raw capture. Consequence for any transform seam (#8/#9/#10): a retry after a config edit re-sends the old shape, a replay sends the new one — and re-transforming on retry is *excluded*, not merely undesirable, because the bytes would then differ from `dispatched_payloads.body` (breaks PRD-05/ADR-013's "what is stored is what was sent") and fixing that needs a mid-retention rewrite. `dispatched_payloads` is `UNIQUE(webhook_event_id)`, so a replay **overwrites** it — the store is already last-dispatch-wins.

**Column-type choices that bite later:** prefer `string(32)` + a backed PHP enum cast over the house `enum(...)` column when the value set is meant to grow (adding a case then costs no migration); prefer `longText` + `array` cast over MySQL `json` for anything #10 might later encrypt (a `json` column can never carry an `encrypted*` cast — see the `headers` gotcha above). MySQL **and** SQLite ignore NULLs in unique indexes, so `nullable_boolean` + `UNIQUE(parent_id, flag)` is a portable partial-unique index for "at most one X per parent".

**Retention GC hold set (`PurgeExpiredPayloads::applyHolds()`) — gotchas for any lifecycle work:**
- Six conjunctive holds H0–H5, written **once** and applied to both the selection `SELECT` and the erase `UPDATE`'s own `WHERE` (the compare-and-set). H5 arrived with #6/ADR-015 D7. Never add a hold to only one of the two.
- **One config knob, two different anchors.** `retention.dispatch_horizon_minutes` bounds H4 against `webhook_events.created_at` **and** H5's `pending` clause against `deliveries.created_at`. Because any collectable event is already ≥ the retention window old, **H4's age branch is unreachable in practice** — the knob materially governs H5 only.
- **Corollary that traps people:** for the *original* dispatch, `deliveries` rows are created at ingest, so the H5 age test runs at ingest+window — **no horizon value can ever close an original-dispatch hold gap**; it's unbounded-hold or nothing. Tuning the horizon only helps rows created *late* (replay dispatches, whose `deliveries` rows are minted at replay time).
- **Unbounded holds are rejected by name, three times** (ADR-012 §Alternatives, ADR-015 D7, ADR-016 D2): a never-settling row immortalizes a payload, contra PRD-05 AC6. Don't re-propose one.
- **Nothing terminalizes a stranded Async `pending` delivery.** `SweepDueRetries` touches only `retrying`; `SweepStalledFifoDispatches` pass (c) only *reads* non-terminal deliveries. FIFO self-heals (lease reaper → re-`DeliverStep` inline), Async does not. Assume `pending` can persist forever on Async.
- Async attempt-1 jobs (`DeliverStep` → `DeliverToDestination`) **carry their bytes** in the `DeliveryUnit`; only `ProcessIngestedWebhook` (ingest entry *and* replay) re-reads the stored row. That asymmetry is what makes most GC-vs-dispatch races harmless — if attempt-1 ever moves to by-reference, every such argument inverts.

**Native team authorization seam** (hand-rolled Jetstream-style, no auth library):
- `App\Enums\TeamRole` (Owner/Admin/Member) — `permissions(): array<TeamPermission>` static bundle per role; `Owner => TeamPermission::cases()`. Also `hasPermission()`, `level()`/`isAtLeast()`, `assignable()`.
- `App\Enums\TeamPermission` — string-backed, namespaced (`team:`, `member:`, `invitation:`). Team-admin only until #2 adds `proxy:` cases.
- `App\Concerns\HasTeams` (on User) — `teamRole(Team)` reads role from `team_members` pivot (`Membership.role` cast); `hasTeamPermission(Team, TeamPermission)` is the team-scoped gate; `toTeamPermissions(Team)` builds the `App\Data\TeamPermissions` boolean DTO shared to the frontend for conditional UI.
- Policies consume `$user->hasTeamPermission($team, TeamPermission::X)` (see `TeamPolicy`). `ProxyPolicy` was membership-only through #1; #2 (ADR-009) makes it permission-based on the same seam.
