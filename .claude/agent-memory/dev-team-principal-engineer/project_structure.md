**Engine and migration traps**
- The migration set is **MySQL-only and cannot run on SQLite at all** (`webhook_events.body` is LONGBLOB via a raw `ALTER TABLE … AFTER`, plus three more raw-DDL migrations). `.env.example` and `config/database.php` still default to `sqlite` — a trap, not a working default. `./vendor/bin/sail test` (MySQL 8.4; CI 8.0) is the only way the suite runs, so **any portability claim must be verified at the query-builder level, never by running the suite on SQLite**.
- `$table->binary()` maps to MySQL `BLOB` (64 KiB) — too small for the `encrypted` cast envelope (~35% overhead) at the ADR-006 body cap, so any new payload-content column needs raw LONGBLOB DDL. `byte_size` is always the plaintext length, computed before the cast.
- **A MySQL `json` column can never carry an `encrypted*` cast**: MySQL validates JSON on write and the cast emits a base64 envelope ⇒ error 3140 on every write. Encrypting one means a type change to `MEDIUMTEXT` (not `TEXT` — 64 KiB minus the envelope is a silent-truncation cliff) plus a drop-and-re-add, since existing plaintext rows cannot be decrypted by the new cast. Prefer `longText` + `array` cast over `json` for anything that might later be encrypted.
- Prefer `string(32)` + a backed PHP enum over an `enum(...)` column wherever the value set may grow — adding a case then costs no migration. That reasoning survives even when only one case remains, so do not narrow such a column later.
- MySQL **and** SQLite ignore NULLs in unique indexes, so `nullable boolean is_current` + `UNIQUE(parent_id, purpose, is_current)` is a portable "at most one current per parent".
- Neither MySQL 8.0 nor SQLite has a **percentile** function (portable exact form: count `n`, then `ORDER BY col LIMIT 1 OFFSET CEIL(p*n)-1`) or a portable **hour-truncating** function (`DATE()` is portable; `DATE_FORMAT`/`strftime` are not). Series densification matches SQL bucket keys to PHP-formatted keys by string equality, so the two formats must agree exactly — and an hourly bucket makes any app/DB timezone mismatch displace every point, not a minority.

**Dispatch seam**
- `webhook_events` is raw-only immutable by construction (ADR-010): it cannot hold dispatch/processing/claim state, so any per-event ordering or claim state needs a **sidecar table**, and queued jobs dispatch **by reference** (`ingest_id`, context rebuilt on the worker).
- **Anything that must happen before the upstream 2xx cannot be a pipeline step.** `ProcessIngestedWebhook` is dispatched async, so a step runs after the response has been returned; such work belongs in `IngestController`, pre-dispatch. This is why raw capture was moved out of the pipeline.
- **A step that returns `$ctx` without `$next` strands the dispatch.** Deliveries rows are created `pending` before the pipeline runs. On FIFO the dispatch then parks at `awaiting_retry` with no lease and no retry schedule, neither sweeper pass releases it, the proxy's line stalls **permanently**, and hold H2 immortalizes its payloads. Async strands more quietly (the badge reads pending forever). Any new short-circuiting step must first CAS that dispatch's `pending`/`retrying` deliveries to `failed` (plus `DeliveryExhausted` once per row and **no** `delivery_attempts` row — `RetryDelivery::terminalizeCleaned()` is the precedent). `CaptureDispatchedStep`'s cleaned-parent short-circuit has this bug today (narrow: GC must erase during a dispatch).
- **Retry and replay are mechanically different.** `RetryDelivery` re-sends the *recorded dispatched bytes*; replay mints a new `dispatch_uuid` and re-runs the whole pipeline from the raw capture. So a retry after a config edit sends the old shape and a replay sends the new one — and re-transforming on retry is *excluded*, not merely undesirable, because the bytes would then diverge from `dispatched_payloads.body` ("what is stored is what was sent"). `dispatched_payloads` is `UNIQUE(webhook_event_id)`, so replay overwrites: the store is already last-dispatch-wins.
- **`StoredPayloadLookup::dispatchedBytesFor()` always resolves because its gate is a positive assertion, not an absence**: `dispatched_payloads.body IS NULL` (or no row) *means* "output was byte-identical to the raw capture". It is total only because every payload-mutating step is enhanced-mode-only and `CaptureDispatchedStep` is composed last, immediately before `DeliverStep`. A simple-mode transform step, or a step composed after the capture, would silently deliver stale bytes through every by-reference path.

**FK and index topology**
- `fifo_dispatches.webhook_event_id` is `constrained()` = RESTRICT (as are the `team_id`/`proxy_id` FKs), so deleting an event row **fails** until its fifo row goes first — a fail-loud safety net, fatal if unnoticed.
- `delivery_attempts` reaches an event only through **`ingest_id`** (plain uuid, no FK, plain index), so attempt rows survive an event delete structurally — and `ingest_id` is **the only join that reaches every attempt** (replay dispatches under the event's existing `ingest_id`, and pre-#6 rows have `delivery_id` NULL, so joining through `deliveries` silently drops them).
- `webhook_events` is indexed `(team_id, created_at)` and `(proxy_id, created_at)`; a bare `created_at` range scan has no index.

**Resolver and config choke points**
- Single-resolver services are the choke points: `RetryPolicy`, `StoredPayloadLookup`, `RetentionPolicy`. Guard new `config()` reads with the fail-loud `positiveConfigInt()` idiom; config files are one-per-concern. Two standing breaches: `SweepDueRetries` reads `retry.sweep_grace_seconds` directly (blank env ⇒ `(int)'' = 0` ⇒ cutoff `now()` ⇒ sweeps every retrying delivery every minute), and `ProxyResource` reads the retry columns directly.
- `ingest.fifo_lease_seconds` is a bare `(int) env()` read in two places with no guard: blank env ⇒ lease `0` **and** `expireAfter(0)` ⇒ a `RedisLock` with no expiry at all — an instant-reap storm plus a permanently leaked per-proxy lock.
- `proxies.mode` is read behaviourally in exactly one place (`PipelineFactory::stepsFor()`). Enhanced-only *steps* are gated structurally by composition; enhanced-only *configuration* is gated at resolution time inside its resolver, because it is consulted outside the pipeline (settle time, delayed retries) and can never be a step.
- **Nothing snapshots mode or policy** — jobs are by-reference and the proxy is re-loaded per run, so "current config governs" is structural. `DeliverToDestination` compares `attemptNumber >= limit`, so a shrinking limit terminalizes instead of looping.
- **`Delivery::proxy()` and the `DeliveryAttempt` relations are plain `belongsTo` while `Proxy` uses `SoftDeletes`** ⇒ null at runtime for a soft-deleted proxy, and PHPStan cannot see it (`@property-read Proxy $proxy`). Use `withTrashed()` (`ProcessIngestedWebhook` is the precedent). `DeliveryUnitResolver`'s `withTrashed()` load must stay for this reason alone.

**Retention GC**
- Six conjunctive holds H0–H5 in `PurgeExpiredPayloads::applyHolds()`, written once and applied to both the selection `SELECT` and the erase `UPDATE`'s own `WHERE` (the compare-and-set). Never add a hold to only one of the two.
- One knob, two anchors: `retention.dispatch_horizon_minutes` bounds H4 against `webhook_events.created_at` and H5 against `deliveries.created_at`. **H4's age branch is unreachable in practice**, so the knob materially governs H5 only. And for an *original* dispatch, deliveries rows are created at ingest, so **no horizon value can ever close that hold gap** — tuning only helps rows minted late (replay dispatches).
- **Unbounded holds are rejected by name three times** (ADR-012 Alternatives, ADR-015 D7, ADR-016 D2): a never-settling row immortalizes a payload. Do not re-propose one.
- **Nothing terminalizes a stranded Async `pending` delivery** — `SweepDueRetries` touches only `retrying`, and the FIFO sweeper only reads non-terminal deliveries. FIFO self-heals through the lease reaper; Async does not. Assume `pending` can persist forever on Async.
- Async attempt-1 jobs carry their bytes in the `DeliveryUnit`; only `ProcessIngestedWebhook` (ingest entry and replay) re-reads the stored row. That asymmetry is what makes most GC-versus-dispatch races harmless — **if attempt 1 ever moves to by-reference, every such argument inverts**.

**FIFO claim-lease**
- The lease is stamped once at claim time and **never renewed**, and the stalled sweeper reaps every expired `claimed` row unconditionally — it cannot know a worker is still running. `WithoutOverlapping`'s TTL is deliberately equal to the lease, so the overlap lock offers zero protection past lease expiry. Nothing in the application closes the concurrency window.
- **The only thing preventing two live advancers is a config value**: Horizon `supervisor-default` timeout (60) < `ingest.fifo_lease_seconds` (90). Full chain: `DeliverToDestination::TIMEOUT_SECONDS (15) < 60 < 90 < redis retry_after (180)`. With FIFO's inline sequential fan-out, "timeout must exceed the longest legitimate job" and "timeout must stay under the lease" are **jointly unsatisfiable for five or more destinations**.
- `UNIQUE(delivery_id, attempt_number)` stops a duplicate attempt **row**, never a duplicate **send**: `DeliverToDestination::resume()` re-drives a row still in status `dispatched` and cannot distinguish a crashed worker from one sending right now. The guard covers sequential at-least-once redelivery only.
- `AdvanceProxyFifoQueue::settleOrHold()`'s settle branch is a blind `update()` by primary key, not a CAS (its hold branch is a CAS), and the read-then-write is concurrency-free **only because inline delivery guarantees no delivery of that dispatch can settle concurrently**. Queued FIFO fan-out turns that into a routine race.
- `WithoutOverlapping`'s `$releaseAfter` defaults to `0` and the advancer never calls `->dontRelease()`, so a losing advancer is released and then fails `MaxAttemptsExceeded` under `tries => 1`. Both the docblock and `config/horizon.php`'s comment claim it is "simply dropped" — **they are wrong**.
- **FIFO puts no payload on the queue at all** (the advancer carries only `int $proxyId`; fan-out is inline), while Async serializes the whole `DeliveryUnit` into Redis and thus into `failed_jobs`. Moving FIFO fan-out onto the queue extends that exposure to FIFO — an Owner-gated security consequence, not a free change.

**Queue payload**
- **`ShouldBeEncrypted` does not reach a `lorisleiva/laravel-actions` job.** `Queue::jobShouldBeEncrypted()` tests the serialized `JobDecorator`, which declares a fixed public-property set with no `shouldBeEncrypted`, so putting the interface on an Action is a **silent no-op**. Reaching it means overriding `makeJob()` per action or swapping `ActionManager::$jobDecorator` globally. Laravel encrypts only `data.command`, never the JSON envelope.
- **`SerializesModels` does reach it.** `serializeProperties()` runs `array_walk` one level and `getSerializedPropertyValue()` does not recurse, so a **top-level** model argument becomes a `ModelIdentifier` but a DTO that *holds* a model serializes the whole model — which is why today's `dispatch($unit)` puts payload, headers and the full `Destination` into the job. Restoration uses `newQueryForRestoration()` = `newQueryWithoutScopes()->whereKey()->useWritePdo()->firstOrFail()`, so it **bypasses every global scope** (soft deletes and `TeamScope` alike); `handleModelNotFound()` reads `deleteWhenMissingModels`, absent by default, so the default on a missing model is **fail the job**, and either way the handler never runs.
- ADR-015 Decision 5 already forbids payload bytes in a retry job's arguments; attempt 1 is the only delivery job in the system carrying a payload. `RetryDelivery` is the by-reference template.
- **Horizon is a second durable store of every job payload** — it writes the raw payload string verbatim, and `horizon.trim` keeps failed and monitored for 7 days, untouched by `queue:prune-failed`. A payload in a job therefore lands in two independent 7-day stores.
- **Three retention literals must stay ordered below `retention.days`, and no test enforces it**: `queue:prune-failed --hours 168` (a literal in `routes/console.php`), Horizon's `trim.failed`/`recent_failed`/`monitored` = 10080 minutes, and env `RETENTION_DAYS` (default 30).
- Both durable payload stores are encrypted at rest under **ADR-010 Amendment B's binding `APP_PREVIOUS_KEYS` rule** — never drop a prior key until a re-encryption pass has rehashed every row. Encrypting a *queue* message would add a ciphertext location with **no row to re-encrypt**: a new failure class, not a covered one.
- **Driver-size mismatch, live today on Async**: `ingest.max_body_bytes` defaults to 52,428,800 (50 MiB) against **SQS's 256 KiB** message cap. Redis and the `database` driver both tolerate it, which is why it stays invisible until a driver change.

**Secret and PII leak seams**
- **`QueryException::formatMessage()` interpolates bindings into the message**, and that message reaches `failed_jobs.exception`, Horizon's own 7-day copy, and the log. Nothing plaintext leaks today **only because the `encrypted*` casts run at attribute-set time and `Model::performInsert()` binds `getAttributes()`** — a hand-rolled `Crypt::encryptString()` assignment anywhere would put plaintext into all three. `IngestController`'s bare `report($e)` already writes ciphertext of body and headers into `storage/logs`, a store with no retention pass and no inventory entry.
- **`Arr::forget()` supports dot notation but not wildcards**, and `Handler::invalid()` flashes `Arr::except($request->input(), $dontFlash)`. With `SESSION_DRIVER` defaulting to `database`, a submitted secret in a nested key (`destinations.*.credential_secret`) lands in the `sessions` table where `dontFlash` cannot reach it — it needs a `failedValidation()` scrub. Inertia forms never read `old()`, so scrubbing loses nothing.
- `Inertia::flash` goes to the session store and page props go to browser history state; neither may carry a secret. A one-time secret reveal must be a plain JSON XHR with `no-store`.
- **Nothing in `app/` calls `Cache::` or `cache()` at all** — no cache copy of anything, ever (useful for at-rest inventories).
- **"Key absent" versus "key present and null" survives validation and dies one layer later — never build a signal on it.** `Validator::validated()` skips missing keys while an explicit `null` reaches it, but `ProxyController::destinationRows()` normalises every submitted destination field with `isset()`, destroying the distinction with no error and no failing test. **Encode intent as a positive value (a sibling boolean), never as an absence.** Wildcard-sibling rules (`required_with:destinations.*.credential_secret`) do work and are already used on that form.

**Ingest raw body**
- The ingest route is registered **outside the web group** (`bootstrap/app.php` `withRouting(then:)` → `routes/ingest.php`), so `TrimStrings`/`ConvertEmptyStringsToNull` never run on it. Nothing in the path mutates `Request::$content`, Symfony caches the first `getContent()`, and there is no Octane. The route accepts POST and PUT only.
- **`multipart/form-data` means `php://input` is empty, so `getContent()` returns `''`** — `webhook_events.body` already stores nothing for a multipart sender, and any HMAC over it fails closed. `application/x-www-form-urlencoded` *is* readable from `php://input`, but that depends on SAPI and `enable_post_data_reading`; verify at runtime, because a wrong answer is silent.
- **`trustProxies(at: '*', … HEADER_X_FORWARDED_HOST …)` makes `getHost()`/`fullUrl()` caller-controllable** (deliberate — no enumerable load-balancer range yet). Consequence: **any value resolved from the live request is a signature-oracle vector**; such a value must come from stored proxy configuration.
- **No source IP is captured anywhere**: no column on `webhook_events`, and `IngestController` never calls `$request->ip()`. Adding one means new capture, a new column, and a retention position.

**Outbound headers and the secret machinery (post-ADR-026)**
- Inbound verification was **removed in full** by ADR-026 (Owner ruling, 2026-08-28): forward all headers, strip only the transport-scoped minimum, no inbound validation anywhere. `app/Verification/` is gone. `DeliveryUnit::STRIPPED_HEADERS` is now `host` plus hop-by-hop plus `content-length` — **the service strips no provider signature header at all**, so any "we strip provider signatures" claim is false.
- **`App\Support\StandardWebhooks::verify()` survives as the *outbound* signing suites' receiver-side oracle** — they call it to prove the emitted signature is verifiable by a conforming recipient. Its name makes it the likeliest casualty of a future cleanup; deleting it would reduce those suites to asserting a header is present. `TOLERANCE_SECONDS` is `verify()`'s own replay window.
- **`SecretStore` (`app/Services/`) is purpose-parameterised end to end with no per-purpose branch** — every method takes a `SecretPurpose`, and `liveFor`/`replace`/`generate`/`endOverlap`/`disable`/`statusFor` are each load-bearing for outbound signing. Same for `ProxySecret`, `RotationOverlap`, `SecretUnavailableException`, `ExpireProxySecrets` and `PurgeExpiredProxySecrets`. **Rule any removal at the level of the method, never the class — a grep-driven removal by keyword deletes the rotation engine signing runs on.**
- **`ProxySecret::$casts` maps `purpose` to `SecretPurpose`, so an enum case and its rows are one change**: removing a case while rows carry that string makes every hydration throw. Land the case removal and the row deletion in the same task.
- **Forwarding `authorization` makes the ADR-023 credential collision the ordinary case.** PRD-10 AC30 defaults a destination credential to the `Authorization` header name and removal-then-addition resolves it (added wins), so two destinations of one proxy can legitimately receive different `Authorization` values and nothing in the interface says so.

**Frontend**
- `resources/js/routes/` is **Wayfinder-generated** — removing a route removes the helper; never hand-edit.
- **Removing a prop key server-side before removing its reader is a runtime break TypeScript will not catch** (the interface still declares it). Surface first, backend second.
- **`ProxyResource` is one class serving `index()`, `show()` and `edit()`** — anything added lands on read and write surfaces at once, and a write-only field means a second resource class, not a flag. `create()` renders no proxy resource (Create.vue hard-codes blank state), so anything the create form needs must be a page prop. `ProxyResource.destinations` loads live destinations only; a surface that must show soft-deleted destinations needs its own row set.
- **Display helpers key off `null`, not off mode**: `proxyRetryAttemptLimitDisplay(null)` renders `5 (default)` while a configured `5` renders bare. A resource that emits the *effective* value silently changes rendering for every unconfigured proxy — emit `null` to mean "the system default governs".
- **Distinguish mount-seeded persisted values from in-session typed input** (`ProxyForm.vue`); conflating them destroys user data. `watch(isEnhanced, …)` fires only on an in-session mode change, never on mount, so a clear-on-downgrade arm with no symmetric **up** arm re-seeding from `props.initial` (with the mount-time `?? ''` normalisation, applied **unconditionally** — idempotent, and the Create and NULL-column cases then fall out with no branch) writes NULL over the persisted policy on the next save. **Never write a default literal into a field**, or an unconfigured proxy silently becomes a configured one. The submit `transform()` keys off the **submitted mode**, never field state — that is what keeps `prohibited_if:mode,simple` satisfiable.
- `resources/js/components/PasswordInput.vue` already exists (masked input plus eye toggle, no `autocomplete="off"`).
- **Inertia SSR is `enabled => true` but there is no `ssr.ts`, no `ssr` vite input and no `bootstrap/ssr` bundle** — nothing renders server-side; treat SSR-safety as contingent, not required. **No frontend test framework exists**, so canvas work is manual-verify only, and `public/hot` plus a live dev server is how a "verified against a build" claim goes wrong.
- `canvasKit.ts` already solves CSS-token colours: read custom properties verbatim, then normalise by round-tripping through a 2D context `fillStyle`, because the production minifier rewrites `hsl()` to hex. Never pattern-match token text. `--chart-1`…`--chart-5` exist for both themes.

**Analytics and list read seams**
- **`ApplyTeamScope` registers `TeamScope` on `Proxy`, `Destination` and `DeliveryAttempt` only — not on `Delivery`, not on `WebhookEvent`.** Any query over those two must carry its own `team_id`; leaning on the middleware gives a right answer for attempt-grained figures and a wrong one for delivery-grained ones.
- **A terminal row's `updated_at` is frozen on both fact tables** (every write is a CAS keyed on a non-terminal status; GC writes neither), which is what makes it usable as a time anchor. A blind `save()` on either table would silently move history.
- The two counting units live in disjoint tables (`deliveries` versus `delivery_attempts`), so "never reconciled against each other" and the pre-#6 include/exclude split are structural — there is no filter clause to forget.
- **The analytics window is built in three places and two of them disagree**: `DeliveryStatistics::windowStart()` is rolling, `seriesWindowStart()` is calendar-day aligned, and `ProxyEventController` builds a third rolling copy. The trend series and the headline beside it therefore cover different spans (and a 24h window rendered one point). Collapse them onto one definition before any bucket or window work.
- **`ProxyEventController::applyFilters()` builds the `$start`/`$end` pair once** and substitutes it into whichever branch it takes, so changing what range the list covers is a one-line substitution there and never a second range clause. But **`resolveFilters()` short-circuits to a null predicate when the known filters all fail to resolve, so a newly added parameter is silently swallowed unless that condition is widened too.** The Events list carries no query filter today and its pagination navigates `props.events.links` via `router.get`, so any added filter needs `->withQueryString()` or page 2 drops it.
